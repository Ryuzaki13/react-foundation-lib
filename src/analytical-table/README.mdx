# Analytical Table: модель полного снимка

`@ryuzaki13/react-foundation-lib/analytical-table` строит дерево, группировки,
фильтры, вычисляемые значения и итоги уже загруженных данных. Модуль работает в
SSR и браузере без React hooks, DOM, QueryClient, serverFn или OData. Загрузка,
отмена запросов, ошибки и авторизация остаются у транспорта потребителя.

Для одного расчёта используйте `buildAnalyticalTableModel`. Для таблицы, в которой
пользователь меняет фильтры, сортировку и раскрытие, один раз скомпилируйте описание
и создайте runtime на текущий снимок. Оба способа используют один вычислительный
конвейер и возвращают `AnalyticalTableModel`.

## Один вызов

Прежняя точка входа сохраняет сигнатуру и подходит для разового построения модели,
экспорта или простого потребителя без повторных изменений представления.

```ts
import { buildAnalyticalTableModel, type AnalyticalSnapshot } from "@ryuzaki13/react-foundation-lib/analytical-table";

const snapshot: AnalyticalSnapshot = {
	rows: [
		{ id: "order:1", values: { customer: "Компания А", amount: 100 } },
		{ id: "line:1", parentId: "order:1", values: { amount: 100 } }
	]
};
const model = buildAnalyticalTableModel({
	snapshot,
	columns: [
		{ id: "customer", kind: "dimension" },
		{ id: "amount", kind: "measure", aggregate: "sum" }
	],
	state: {
		grouping: [{ id: "customer", keyColumnIds: ["customer"] }],
		sorting: [{ id: "amount", desc: true }],
		expandedRowIds: "all"
	}
});
// Общий итог — 100: дочерняя детализация не прибавляется к корню второй раз.
```

## Описание и runtime для интерактивной таблицы

`compileAnalyticalTableDefinition` проверяет описание, индексирует поля и
компилирует зависимости формул. `createAnalyticalTableRuntime` готовит исходные
строки одного снимка; `runtime.getModel(state)` меняет его представление.

```ts
import {
	compileAnalyticalTableDefinition,
	createAnalyticalTableRuntime,
	type AnalyticalGroupingLevel,
	type AnalyticalSnapshot,
	type AnalyticalSorting
} from "@ryuzaki13/react-foundation-lib/analytical-table";

const definition = compileAnalyticalTableDefinition({
	columns: [
		{ id: "customerName", label: "Покупатель", kind: "dimension" },
		{
			id: "averagePrice",
			label: "Средняя цена",
			kind: "measure",
			calculate: {
				dependencies: ["amount", "quantity"],
				compute: (values) => (Number(values.quantity) > 0 ? Number(values.amount) / Number(values.quantity) : null)
			}
		}
	],
	dataFields: [
		{ id: "customerId" },
		{ id: "quantity", aggregate: "sum" },
		{ id: "price" },
		{
			id: "amount",
			aggregate: "sum",
			calculate: { dependencies: ["quantity", "price"], compute: (values) => Number(values.quantity) * Number(values.price) }
		}
	],
	grandTotalsScope: "filtered"
});
const snapshot: AnalyticalSnapshot = {
	rows: [
		{ id: "order:1", values: { customerId: "a", customerName: "Компания А", quantity: 2, price: 30 } },
		{ id: "order:2", values: { customerId: "a", customerName: "Компания А", quantity: 1, price: 120 } }
	]
};
const runtime = createAnalyticalTableRuntime({ definition, snapshot });
const grouping: readonly AnalyticalGroupingLevel[] = [{ id: "customer", keyColumnIds: ["customerId"], displayColumnIds: ["customerName"] }];
const sorting: readonly AnalyticalSorting[] = [{ id: "averagePrice", desc: true }];

const initial = runtime.getModel({ grouping });
const sorted = runtime.getModel({ grouping, sorting });
const expanded = runtime.getModel({ grouping, sorting, expandedRowIds: "all" });
// Итоговая средняя цена — 60: (2 × 30 + 1 × 120) / (2 + 1).
// Сортировка и раскрытие не запускают формулы и агрегации повторно.
```

`columns` — столбцы представления. Колонка, которую пользователь временно скрыл,
остаётся в этом массиве: её видимость управляется UI. `dataFields` — служебные
поля с теми же возможностями вычисления, сравнения и агрегации; они доступны
формулам и итогам, но не попадают в `model.columns`. Поэтому зависимость вроде
`amount` не требует фиктивной скрытой колонки интерфейса. Идентификаторы уникальны
в общем каталоге `columns` + `dataFields`; зависимости формул должны быть объявлены
в одном из этих массивов. Поля, используемые только как ключи или подписи групп,
могут ссылаться прямо на `values` без отдельного дескриптора.

Runtime хранит **последний результат каждого этапа** внутри своего экземпляра.
Глобального кэша, истории снимков или транспортного кэша здесь нет. Массивы фильтров,
группировок, сортировки и раскрытия сравниваются по ссылке. Сохраняйте ссылку, пока
содержимое не изменилось; новый равный массив может повторно запустить свой этап.
Мутировать описание, снимок, элементы состояния или их массивы после передачи нельзя.

| Что изменилось                         | Что пересчитывается                                                                                 |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Описание, поля или правила вычисления  | Новая компиляция и новый runtime: исходные формулы и все следующие этапы.                           |
| `snapshot.rows`                        | Новый runtime с прежним скомпилированным описанием: исходные формулы и все следующие этапы.         |
| Фильтры                                | Отбор, группировки и итоги, затем сортировка и раскрытие. Исходные формулы повторно не исполняются. |
| Группировки                            | Группировки и итоги, затем сортировка и раскрытие. Исходные формулы и готовый отбор сохраняются.    |
| Сортировка                             | Порядок соседних строк и индексы; затем применяется раскрытие. Формулы и итоги сохраняются.         |
| Раскрытие                              | Флаги раскрытия и индексы видимости. Формулы, группировки и итоги сохраняются.                      |
| Ширины, закрепление, видимость колонок | Это состояние UI; оно не входит в вычислительный runtime.                                           |

Для новых `rows` создавайте новый runtime: существующий экземпляр не переключает
снимок. В React описание можно мемоизировать по его конфигурации, runtime — по
скомпилированному описанию и `snapshot.rows`. Обновление времени запроса при прежней
ссылке `rows` не требует нового runtime. Изменение реестра используемых формул также
требует повторной компиляции описания.

## Данные и карта исходников

`AnalyticalSnapshot<T>` содержит `rows`. Строка имеет стабильный `id`, необязательный
`parentId`, `values`, предметный `kind` и исходный DTO `original`. Номер позиции не
подходит для ID: обновление и сортировка должны сохранять identity. Runtime не
мутирует снимок и не копирует DTO рекурсивно — `original` сохраняет исходную ссылку.

`AnalyticalViewState` содержит только группировки, сортировку, фильтры и раскрытие.
Результат содержит дерево `rows`, все строки `flatRows`, видимые `visibleRows`,
`rowById`, `grandTotals` и `diagnostics`. Индекс `Map` вычисляется локально; передавать
модель через serverFn не требуется. Числа остаются числами; отображение использует
`/formatters` на границе UI или экспорта.

| Каталог           | Ответственность                                                                |
| ----------------- | ------------------------------------------------------------------------------ |
| `definition`      | Контракты описания, каталог полей, проверка зависимостей и компиляция формул.  |
| `runtime`         | Подготовка одного снимка, дерево, фильтрация, группировка, итоги и сортировка. |
| `dynamic-columns` | Календарные интервалы и проекция уже загруженных фактов в динамические ячейки. |
| `projections`     | Раскрытие, согласованные индексы дерева и подготовка экспорта.                 |

Эта карта предназначена для сопровождения исходников. Потребители импортируют
публичные функции и типы только из `/analytical-table`.

## Иерархия, группировки и фильтры

Исходная иерархия строится через `/tree-table`: повторяющиеся ID, сироты и циклы
попадают в диагностику по правилам этого модуля. Пустой ID запрещён. Дополнительная
группировка объединяет только корневые ветви; исходные дети сохраняют родителей.

`AnalyticalGroupingLevel` задаёт `id`, составной `keyColumnIds` и отдельные
`displayColumnIds`. ID группы зависит от пути ключей и типов, а не от подписи или
порядка строк. Число, строка, `null` и `undefined` различаются. Отображаемые поля
берутся из первой строки группы и должны однозначно определяться ключом. Пустой
список ключей и повторяющиеся уровни отклоняются. Сортировка и фильтры требуют
дескриптора поля из `columns` или `dataFields`.

Сортировка действует между соседями каждого уровня и сохраняет исходный порядок
при равенстве. Строки сравниваются через `/string-comparison`, календарные значения —
через `/formatters`; собственная семантика задаётся `compare`.

Фильтры поддерживают `equals`, `notEquals`, `contains`, `startsWith`, `in`, `between`,
`gt`, `gte`, `lt`, `lte`, `empty`, `notEmpty`. Текстовые `contains` и `startsWith` не
зависят от регистра. Условия объединяются через AND и применяются к вычисленным
исходным строкам **до** группировки: совпавший родитель сохраняет всю ветвь,
совпавший ребёнок — путь к нему. Для предметной семантики предусмотрен `filter` поля.

## Итоги и формулы

По умолчанию агрегируются исходные корни: дочерняя детализация не удваивает их
меры. `isAggregateRow` задаёт другую зернистость. `aggregate` поля поддерживает
`sum`, `min`, `max`, `avg`, `count` и callback. Числовые операции принимают только
конечные числа; преобразование DTO выполняет адаптер. Пустое числовое множество
даёт `null`; `count` считает непустые значения, включая ноль и `false`, и даёт 0
для пустого множества.

`aggregate(context)` описания возвращает групповые/общие значения и может
переопределить стандартные агрегаты. Контекст содержит `scope`, `groupingPath` и
исходные строки выбранной зернистости. Взвешенные доли следует вычислять из сумм
числителя и знаменателя, а не усреднять готовые проценты.

`grandTotalsScope: "filtered"` по умолчанию учитывает оставшиеся ветви; `"all"`
сохраняет итог полного снимка при фильтрации. `grandTotals: false` отключает его
расчёт. Сортировка, раскрытие и выбор строк не изменяют состав общих итогов.

`formula` задаёт `formulaId` и упорядоченные `dependencies` для существующего
реестра `/formulas`; им владеет composition root приложения. `calculate` задаёт
зависимости и чистый `compute(values)`. Одновременно задать оба способа нельзя.
Компиляция проверяет уникальность полей, неизвестные зависимости и циклы.

Исходные формулы вычисляются один раз при создании runtime. При изменении фильтров
или группировок зависимые итоговые формулы выполняются над новыми итогами. Явный
агрегат поля, результат `aggregate(context)` и значения пути имеют приоритет над
построчной формулой этого поля: сумма произведений сохраняется, а отношение сумм
вычисляется заново. Формулы должны учитывать отсутствующие поля итоговой строки;
ошибки конфигурации и исполнения не скрываются успешным нулём.

Низкоуровневые `createAnalyticalCalculationPlan(fields, requiredColumnIds?)` и
`calculateAnalyticalValues(values, plan)` остаются доступны для самостоятельных
вычислений; обычному потребителю достаточно скомпилированного описания.

## Календарные столбцы

`createAnalyticalDateColumnsPlan` строит `day/week/month/quarter/year` интервалы с
включительными `from`/`to`; неделя начинается в понедельник. ID содержит
гранулярность и начало периода; крайние интервалы обрезаются диапазоном. По
умолчанию разрешено до 366 столбцов; превышение лимита — ошибка.

Границы и даты фактов имеют контракт **YYYY-MM-DD**. `Date`, число и ISO timestamp
с временем не принимаются как календарные факты: их приводит адаптер с явной
политикой времени. Используются существующий календарный parser и форматтеры:
`formatDateAsODataDate` для машинных дат, `formatDateAsDate` для подписи дня.
Потребитель согласует настройки форматирования и календарную/timezone-политику
SSR и браузера. Неверный диапазон отклоняется; неверные факты и даты вне диапазона
пропускаются.

`projectAnalyticalDateFacts({ rows, facts, plan })` сопоставляет факты по составному
`identityColumnIds`, добавляя ячейки к копиям значений. Порядок, количество и ID
строк сохраняются. Факты с неполным ключом пропускаются, отсутствие фактов даёт
`null`; конфликт с существующим одноимённым полем вызывает ошибку.

`aggregateAnalyticalDateFacts` считает итоги по исходным фактам — это существенно
для `avg`, где среднее от средних неверно. Групповые итоги получают тем же способом
через aggregate callback. Факты с неполным ключом исключаются и из проекции, и из
итогов; допустимую область остальных фактов задаёт потребитель. Дополнительных
запросов эти функции не выполняют.

## Раскрытие и экспорт

`projectAnalyticalTableExpansion(model, expandedRowIds)` доступен отдельно; runtime
уже вызывает его на последнем этапе. Он сохраняет ссылки неизменённых ветвей,
игнорирует неизвестные ID и листья и возвращает переданную модель при неизменном
эффективном раскрытии. При изменении дерева все индексы указывают на актуальные
узлы, а рассчитанные итоги сохраняются.

`projectAnalyticalTableExport` принимает модель, упорядоченные столбцы с
`format(value, row)`, область `all/visible/selected`, `includeGroups` и
`includeGrandTotals`. По умолчанию экспортируются все строки отфильтрованной модели,
включая свёрнутые ветви. `includeGroups: false` убирает только синтетические группы,
сохраняя предметных родителей. Результат содержит заголовки и массивы значений;
создание файла относится к `/excel` или `/table-document`.

Итоги форматируются отдельным `formatTotal(value)`, поскольку у них нет исходной
строки `original`. Без него сохраняются raw значения независимо от форматтера
обычных строк. ID итога — `analytical-grand-total`; при конфликте со строкой модели
подбирается свободный детерминированный суффикс. Выбор области экспорта его не меняет.

Runtime полного снимка не содержит remote paging, sparse placeholders, LRU страниц
или второй кэш загруженных данных. Возможный серверный источник с постраничной
агрегацией должен иметь отдельный транспортный контракт.
