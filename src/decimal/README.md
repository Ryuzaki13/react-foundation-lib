# Точные десятичные значения

Публичный импорт: `@ryuzaki13/react-foundation-lib/decimal`.
Модуль вычисляет конечные десятичные значения как целый коэффициент и число
десятичных разрядов. Строки не переводятся в `number`; округления нет.
React, browser API и дополнительные зависимости не требуются.

```ts
import { addDecimals, compareDecimalRatios } from "@ryuzaki13/react-foundation-lib/decimal";

addDecimals("0.1", "0.2"); // "0.3"
compareDecimalRatios({ numerator: "10", denominator: "3" }, { numerator: "3.33", denominator: "1" }); // 1
```

| API                                                   | Назначение                                                                        |
| ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| `isCanonicalDecimal(unknown, options?)`               | Проверить внешнее значение без преобразования                                     |
| `normalizeDecimal(string, options?)`                  | Убрать начальные и конечные нули; привести отрицательный ноль к `"0"`             |
| `normalizeDecimalLiteral(string, options?)`           | Точно раскрыть научную запись внешнего числа без преобразования значения в number |
| `addDecimals`, `subtractDecimals`, `multiplyDecimals` | Получить точный канонический результат двух операндов                             |
| `sumDecimals(iterable, options?)`                     | Суммировать за один проход; пустой набор даёт `"0"`                               |
| `compareDecimals`                                     | Вернуть `-1`, `0` или `1`                                                         |
| `compareDecimalRatios`                                | Сравнить отношения без деления; знаменатели строго положительные                  |

Каноническая строка содержит знак минус при необходимости, цифры и точку:
`"0"`, `"0.3"`, `"-12.05"`. Пробелы, плюс, экспонента, запятая, начальные
нули и конечные нули дробной части в арифметике отклоняются. Нормализация
допускает только лишние нули; обработка локализованного ввода и внешних JSON
чисел принадлежит соответствующей входной границе.

Для исходной лексемы JSON-числа входная граница использует
`normalizeDecimalLiteral("1e-1")`, получая `"0.1"`. Parser должен сохранить
исходные цифры: передавать `String` уже прочитанного `number` слишком поздно.
Научная запись разворачивается только в пределах `maxLength`; значение
`"1e1000000000"` отклоняется до выделения большого буфера. Прежние API
арифметики и `normalizeDecimal` по-прежнему не принимают экспоненту.

`DecimalOptions.maxLength` задаёт положительный безопасный целый предел длины
входа и результата, включая знак и точку; по умолчанию — 512 символов.
Вход отклоняется до создания `bigint` и выравнивания разрядов. Неверная форма
даёт `TypeError`, неверный предел, overflow результата и недопустимый знаменатель
— `RangeError`. `isCanonicalDecimal` возвращает `false` для неверного значения,
но неверная конфигурация предела также даёт `RangeError`.

Суммирование проверяет каждый промежуточный результат: даже последующее
взаимное сокращение не отменяет уже возникшее переполнение. При сравнении
отношений произведения не сериализуются; они могут превышать предел строки,
оставаясь ограниченными длиной проверенных операндов.

Предметные правила положительности, единиц измерения и допустимости нуля
остаются у приложения. Приватные коэффициенты и разрядность не входят в API.
