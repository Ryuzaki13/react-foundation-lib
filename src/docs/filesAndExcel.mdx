# Файлы, бинарные данные и Excel

Эта страница описывает browser-only API для чтения пользовательских файлов, преобразования base64 и формирования `.xlsx`. Подготовка бизнес-полей, проверка прав доступа и отправка файла на сервер остаются ответственностью host-приложения.

## `file`: чтение файлов и HTTP-заголовки

```ts
import {
	createContentDispositionHeader,
	readFile,
	readImageFile,
	resolveMimeTypeByExtension,
	type ReadFileError,
	type ReadImageError
} from "@ryuzaki13/react-foundation-lib/file";
```

### Когда использовать

- `readFile` — получить `dataUrl` для preview или `ArrayBuffer` для дальнейшей обработки;
- `readImageFile` — то же для изображений с проверкой image MIME и размером изображения;
- helpers Content-Disposition — сформировать безопасный заголовок в browser-compatible/edge runtime коде;
- `resolveMimeTypeByExtension` — определить MIME по расширению, если содержимого для sniffing нет.

### `readFile`

```ts
readFile(file, options?): Promise<ReadFileResult>
```

| Опция                             | Назначение                                        |
| --------------------------------- | ------------------------------------------------- |
| `mode?: "data-url"`               | Режим по умолчанию. Результат содержит `dataUrl`. |
| `mode: "array-buffer"`            | Результат содержит `buffer`.                      |
| `allowedMime?: readonly string[]` | Точный список разрешённых MIME.                   |
| `maxBytes?: number`               | Максимальный размер файла в байтах.               |
| `signal?: AbortSignal`            | Отменяет чтение через `FileReader.abort()`.       |

Возвращаемый discriminated union всегда содержит `file` и `meta` (`name`, `mime`, `size`, `lastModified`). После проверки `result.mode` TypeScript раскрывает либо `dataUrl`, либо `buffer`.

```ts
const result = await readFile(file, {
	mode: "data-url",
	allowedMime: ["application/pdf"],
	maxBytes: 10 * 1024 * 1024,
	signal
});

if (result.mode === "data-url") {
	previewUrl = result.dataUrl;
}
```

`ReadFileError` имеет предсказуемый `code`: `NO_FILE`, `MIME_NOT_ALLOWED`, `FILE_TOO_LARGE`, `READ_ABORTED` или `READ_FAILED`. Обрабатывайте его как ожидаемую ошибку выбора файла, а остальные ошибки не скрывайте.

### `readImageFile`

```ts
readImageFile(image, options?): Promise<ReadImageResult>
```

Поддерживаемые `ImageMime`: `image/png`, `image/jpeg`, `image/webp`, `image/gif`, `image/svg+xml`, `image/avif`. В режиме `data-url` результат дополнительно включает `dimensions` (`width`, `height`). В режиме `array-buffer` декодирование изображения не выполняется.

`ReadImageError` расширяет коды `ReadFileError` значениями `NOT_AN_IMAGE` и `IMAGE_DECODE_FAILED`.

### Дополнительный API `file`

| API                                             | Контракт                                                                                                              |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `buildMeta(file)`                               | Возвращает serializable метаданные `FileMeta`.                                                                        |
| `attachAbort(signal, reader)`                   | Привязывает отмену к `FileReader`; возвращённую функцию cleanup вызывают только custom consumers низкоуровневого API. |
| `assertNotAborted(signal?)`                     | Бросает `ReadFileError("READ_ABORTED")`, если сигнал уже отменён.                                                     |
| `assertValidAllowedMime`, `assertValidAccept`   | Проверяют конфигурацию accept/MIME до чтения.                                                                         |
| `sanitizeFileName(value, fallback?)`            | Удаляет unsafe символы из имени.                                                                                      |
| `encodeFilenameRFC5987(value)`                  | Кодирует Unicode filename для HTTP header.                                                                            |
| `createAsciiFilenameFallback(value, fallback?)` | Создаёт ASCII fallback для старых consumers заголовка.                                                                |
| `createContentDispositionHeader(options)`       | Создаёт `inline`/`attachment` Content-Disposition с `filename` и `filename*`.                                         |

## `binary`: base64 → `Blob`

```ts
import { binaryToBlob, detectMimeType, useBinaryFile } from "@ryuzaki13/react-foundation-lib/binary";
```

| API                                              | Вход и результат                                                                                                                  |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `binaryToBlob(binaryData, mimeType?, isBase64?)` | Создаёт `Blob` из base64/data URL (по умолчанию) или raw binary string (`false`). Пустые или некорректные данные бросают `Error`. |
| `detectMimeType(fileName?, binaryData?)`         | Ищет MIME по расширению, data URL, затем сигнатуре base64. Неопределённый документ трактует как `application/pdf`.                |
| `useBinaryFile(bin)`                             | React hook, возвращает `{ data: { blob, mime } \| null, error: string \| null }`.                                                 |

```ts
const mime = detectMimeType("report.pdf", base64);
const blob = binaryToBlob(base64, mime);
const objectUrl = URL.createObjectURL(blob);

// Владелец UI обязан освободить URL при смене файла/размонтировании.
URL.revokeObjectURL(objectUrl);
```

`useBinaryFile` не создаёт object URL и не освобождает его: это lifecycle конкретного preview-компонента. Hook использует `Blob` и `atob`, поэтому не вызывайте его в SSR или worker без совместимого polyfill.

## `excel`: скачивание `.xlsx`

```ts
import {
	buildExcelAutoFilterRef,
	buildExcelSheetData,
	createTableExcelColumn,
	downloadExcelFile,
	downloadExcelWorkbook,
	downloadResolvedExcelTable,
	downloadResolvedExcelWorkbook,
	resolveExcelCellStyleFromState,
	resolveExcelSheetNames
} from "@ryuzaki13/react-foundation-lib/excel";
```

### Базовый экспорт

`downloadExcelFile({ fileName, columns, rows, autoFilter?, getCellStyle? })` создаёт один лист; `downloadExcelWorkbook({ fileName, sheets })` — книгу из нескольких листов. Это asynchronous browser API, который инициирует скачивание через `write-excel-file`.

```ts
await downloadExcelFile({
	fileName: "users.xlsx",
	columns: [
		{ id: "name", header: "Имя", type: String, width: 28 },
		{ id: "createdAt", header: "Дата", type: Date, format: "dd.mm.yyyy" }
	],
	rows: [{ name: "Анна", createdAt: new Date("2026-07-30") }],
	autoFilter: true
});
```

| Public type/API                             | Назначение                                                                                                           |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `ExcelColumn`, `ExcelRow`, `ExcelCellStyle` | Контракты столбца, строки и стиля ячейки. `type` передаёт в файл истинные `Number`/`Date`/`Boolean`, а не UI-строку. |
| `buildExcelSheetData(args)`                 | Строит данные листа без запуска download; подходит для тестируемой подготовки.                                       |
| `buildExcelAutoFilterRef(columns, rows)`    | Даёт Excel-диапазон или `undefined` для пустой сетки.                                                                |
| `resolveExcelSheetNames(names)`             | Нормализует ограничения Excel (31 символ, forbidden chars) и делает имена уникальными.                               |
| `resolveExcelCellStyleFromState(state)`     | Преобразует `State` в базовый цвет текста Excel.                                                                     |

### Экспорт подготовленной таблицы

`TableExcelColumnDescriptor` связывает generic Excel column с OData type/role и необязательным `formattersPipeline`. Используйте `createTableExcelColumn(descriptor)` для получения типизированного столбца, затем передавайте значения строк без предварительного UI-форматирования.

| API                                                            | Назначение                                                                        |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `resolveTableExcelColumnType(descriptor)`                      | Выбирает `String`/`Number`/`Date`/`Boolean` по OData metadata и роли.             |
| `createTableExcelColumn(descriptor)`                           | Создаёт `ExcelColumn` с Excel-маской числа/даты из published formatter contracts. |
| `downloadResolvedExcelTable({ fileName, table, autoFilter? })` | Скачивает одну уже подготовленную таблицу.                                        |
| `downloadResolvedExcelWorkbook({ fileName, sheets })`          | Скачивает несколько `ResolvedExcelTable` как листы книги.                         |

Не передавайте в `rows` отформатированные через `Intl` строки для числовых и date-столбцов: Excel потеряет сортировку, формулы и формат. Строки создавайте только для действительно текстовых значений.

## Ограничения

- Все три entrypoint ориентированы на DOM/browser; не вызывайте их в server-only коде.
- MIME по имени/сигнатуре не является проверкой безопасности содержимого. Сервер обязан валидировать загружаемые файлы повторно.
- `download*` имеет пользовательский side effect. Вызывайте его из event handler, а не из render/effect при монтировании.
