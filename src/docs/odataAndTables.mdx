# OData metadata, таблицы и формулы

Здесь находятся чистые OData V2 helpers и runtime contracts для TanStack Table. Они не выполняют запросы. Для SAP Gateway transport, SSO, X-CSRF, metadata fetch и TanStack Query operation используйте `@ryuzaki13/react-foundation-api/odata`.

## `odata-service`: metadata и OData V2 values

```ts
import {
	buildEntityPath,
	buildODataFilter,
	buildODataOrderBy,
	odataFormatValue,
	parseServiceMetadata,
	wrapODataParams
} from "@ryuzaki13/react-foundation-lib/odata-service";
```

### Основной поток

```text
metadata XML → parseServiceMetadata → typed metadata/config
  → wrapODataParams + builder/filter/sort → foundation-api transport
  → metadata-aware parse/format → entity/feature mapping
```

Не передавайте в helpers невалидный external JSON как будто он уже соответствует domain model. Metadata parser описывает OData contract, а domain validation/mapping остаётся у host entity/feature.

### Metadata, paths и параметры

| API                                                        | Результат                                                                                                                                             |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `parseServiceMetadata(xmlText)`                            | Парсит OData V2 XML в `ServiceMetadata`: entities, properties, FunctionImports, keys, parameters и типы. Некорректный XML/metadata — ошибка boundary. |
| `resolveMetadataColumnLabel(column)`                       | Label с fallback на column id.                                                                                                                        |
| `collectFilterableColumns`, `collectFilterableColumnsIds`  | Отбирают filterable metadata fields.                                                                                                                  |
| `wrapODataParams(params)`, `unwrapODataParams(params)`     | Разделяют значения параметров и их OData type; используйте перед builder, а не сериализуйте вручную.                                                  |
| `buildParameterEntries`, `buildEntityParameters`           | Строят key/predicate часть entity из metadata и wrapped params.                                                                                       |
| `buildEntityPath`, `buildEntityOperationPath`              | Возвращают metadata-aware путь entity/operation.                                                                                                      |
| `buildFunctionImportParameters`, `buildFunctionImportPath` | Строят FunctionImport URL/query через `URLSearchParams`.                                                                                              |

```ts
const metadata = parseServiceMetadata(metadataXml);
const params = wrapODataParams({ id: "42" });
const path = buildEntityPath(entityMetadata, { service: "DEMO_SRV", target: "Items" }, params);
```

Типы `ServiceMetadata`, `EntityMetadata`, `FunctionImportMetadata`, `EntityColumnProperty`, `ODataMetaType`, `WrappedODataParameters` и `ODataServiceConfig` экспортируются из того же subpath. Параметры entity и FunctionImport — разные OData contracts; не смешивайте их.

### Значения и formatter registry

| API                                                                                                                  | Назначение                                                                                             |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `odataFormatValue(type, value)`                                                                                      | Сериализует primitive в OData literal с escaping/suffix/date semantics.                                |
| `odataParseValue(type, value)`                                                                                       | Возвращает primitive/date или исходное `unknown`, если значение не может быть безопасно преобразовано. |
| `odataParseValueByMetadata(descriptor, value)`                                                                       | Парсит с учётом metadata descriptor, включая ABAP boolean-like поле.                                   |
| `defaultODataTypeValue`, `defaultControlTypeValue`                                                                   | Default value для OData/base control type.                                                             |
| `getBaseTypeFromODataType`, `isODataBooleanType`, `isODataNumericType`, `isODataIntegerType`, `isODataDateType`      | Type classification.                                                                                   |
| `getFormattersFor`, `getFormattersForBaseType`, `getFormatter`, `getFormatterForBaseType`                            | Читают встроенный formatter descriptions по type/id.                                                   |
| `createFormatter`, `createBooleanFormatter`, `createStringFormatter`, `createNumberFormatter`, `createDateFormatter` | Создают typed formatter definitions с Zod input schema.                                                |

### Фильтры, sorts и SQL-like expressions

`FilterExpression<T>` — serializable дерево с `FilterConditionExpression` и `FilterNestedExpression`. Постройте его через `createFilter`, `createFilterEqual`, `createFilterEqualFalsy`, `createFilterContains`, `createFilterBetween`, объедините через `mergeFilterExpressions`, затем вызовите `buildODataFilter` или `buildODataFilterRecursive`.

```ts
const expression = createFilterEqual<{ status: string }, string>("status", "active");
const filter = buildODataFilter(expression);
```

| API                                                                                   | Контракт                                                                                                                     |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `FilterOperation`, `FILTER_OPERATIONS`, `isFilterOperation`, `resolveOperationLabel`  | Стабильный список и validation operator-ов.                                                                                  |
| `Sort<T>`, `toggleSort`, `getSortIndex`, `getSortIndicator`                           | Immutable sort state для UI.                                                                                                 |
| `buildODataOrder`, `resolveEffectiveSorts`, `buildODataOrderBy`                       | Сериализуют sort/grouping для OData.                                                                                         |
| `createSqlFilterEqual`, `createSqlFilterIn`, `createSqlFilterGroup`, `buildSqlFilter` | Отдельный SQL-filter contract: field id предварительно валидируется. Не подставляйте произвольный пользовательский field id. |

`ODataCompiledFilterDefinition`, `sanitizeFilterDefinitions`, `sanitizeFilterValues`, `mergeFilterValuePatch`, `compileFiltersToExpression`, `flattenFilterValuesToODataDependencies` предназначены для serializable UI filter configuration. Санитизация создаёт canonical configuration; не записывайте её поверх активного пользовательского draft без явно названной save/restore boundary.

## `odata`: code/text collections

```ts
import { buildSeparatedArrays, findCollectionPairs, ODataDateFormat } from "@ryuzaki13/react-foundation-lib/odata";
```

| API                                                    | Назначение                                                                |
| ------------------------------------------------------ | ------------------------------------------------------------------------- |
| `buildSeparatedArrays(collection, ...)`                | Разделяет OData collection на code/text arrays для select-like consumers. |
| `findCollectionPairs(...)`                             | Находит code/text pair по collection/dependency filters.                  |
| `ODataDateFormat`                                      | Константы date formats для legacy OData values.                           |
| `CollectionItem`, `CollectionPair`, `DependencyFilter` | Публичные contracts коллекций.                                            |

`useODataCollectionStore` и `odataCollectionConfig` описаны на странице Runtime/state: это UI defaults, а не OData transport/cache.

## `table`: TanStack Table contracts

```ts
import { buildTableColumnLayout, createTableColumnsFromODataMetadata, useTableRowSelection } from "@ryuzaki13/react-foundation-lib/table";
```

`TableColumnDef<TData>` расширяет TanStack `ColumnDef`, а `TableColumnMeta`/`TableColumnFormattingMeta` описывают common metadata. Не мутируйте исходные `ColumnDef`: layout/order/sizing helpers возвращают новое состояние.

| Группа    | Public API                                                                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout    | `resolveTableColumnOrder`, `buildTableColumnLayout`, `TableColumnLayoutItem`, `BuildTableColumnLayoutArgs`.                                                               |
| Order     | `normalizeTableColumnOrder`, `reorderTableHeaderColumns`, `resolveReorderedTableHeaderColumns`, `TableColumnOrderState`.                                                  |
| Sizing    | `DEFAULT_TABLE_COLUMN_MIN_WIDTH`, `normalizeTableColumnWidth`, `normalizeTableColumnSizing`, `patchTableColumnWidth`, `removeTableColumnWidth`, `TableColumnSizingState`. |
| Selection | Row/cell modes, pruning/toggle helpers, `shouldActivateTableCellSelection`, `useTableRowSelection`.                                                                       |
| Metadata  | `getTableColumnMeta`, `getTableColumnFormattingMeta`, `resolveTableLength`, `isTableInteractiveElement`.                                                                  |

`useTableRowSelection` синхронизирует selection state с TanStack Table. Передавайте устойчивый `getRowId` на business identity, не array index: изменяемая сортировка/фильтрация иначе свяжет selection с неверной строкой. Cell-selection хранит координаты `rowId + columnId`; режим `primary-modifier` активируется безопасным Ctrl/Command без Shift/Alt.

### Metadata-driven OData adapter

| API                                                          | Назначение                                                                                |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `createTableColumnsFromODataMetadata(options)`               | Строит `TableColumnDef` из OData metadata.                                                |
| `enrichTableColumnsWithODataFormatting(columns, options)`    | Добавляет typed formatting metadata к существующим columns без изменения OData transport. |
| `createTableColumnVisibilityFromODataMetadata(...)`          | Формирует initial column visibility.                                                      |
| `resolveTableColumnFormattingContextFromODataColumn(column)` | Создаёт formatter context для одного metadata column.                                     |
| `resolveStableColumnId(column)`                              | Определяет устойчивый id table column.                                                    |

`meta.formatting` — экспериментальный presentation contract, не OData request. Если pipeline требует дополнительные runtime fields, owner Query должен расширить select/dependencies через documented formatter pipeline API до fetch.

## `tree-table`: построение дерева

```ts
import { buildTreeTableRows, transposeFlatRowsToTreeTableRows } from "@ryuzaki13/react-foundation-lib/tree-table";
```

| API                                                                                                         | Контракт                                                                  |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `buildTreeTableRows(rows, hierarchy)`                                                                       | Строит `TreeTableBuildResult`: tree rows и diagnostics от flat hierarchy. |
| `transposeFlatRowsToTreeTableRows(rows, options)`                                                           | Создаёт display tree/синтетические nodes из flat rows.                    |

Функции не меняют исходные rows. Используйте explicit stable row/parent ids; не рассчитывайте на визуальный label как идентичность.

## `formulas`: registry calculated columns

```ts
import {
	compileTableFormula,
	configureTableFormulaRegistry,
	createTableFormulaRegistry,
	executeTableFormula,
	validateTableFormulaDependencies
} from "@ryuzaki13/react-foundation-lib/formulas";
```

### Инициализация

Host владеет `TableFormulaDefinition[]` и один раз, до первого compile/validate/execute, создаёт и устанавливает registry:

```ts
const registry = createTableFormulaRegistry([
	{
		id: "margin",
		name: "Маржа",
		description: "Выручка минус себестоимость",
		fn: (ctx) => ctx.num(0) - ctx.num(1)
	}
]);
configureTableFormulaRegistry(registry);
```

| API                                                  | Результат                                                                                                            |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `createTableFormulaContext({ keys, rowData })`       | Контекст `key/value/num(index)` для formula function.                                                                |
| `createTableFormulaRegistry(definitions)`            | Проверяет non-empty unique ids и создаёт immutable registry.                                                         |
| `getTableFormulaList`, `getTableFormulaById`         | Читают активный registry.                                                                                            |
| `compileTableFormula({ formulaId, keys? })`          | Компилирует executor или controlled compile result.                                                                  |
| `executeTableFormula({ formulaId, keys?, rowData })` | Одноразово выполняет formula и возвращает `TableFormulaExecutionResult`, не выбрасывая formula runtime error наружу. |
| `validateTableFormulaDependencies(args)`             | Проверяет formula id, dependency availability, out-of-range/unused indices.                                          |

Formula function возвращает finite number. Ошибочные состояния (`formula_not_found`, `runtime_error`, `invalid_result`) являются данными результата, а не поводом silently подставить ноль. Обработайте их у formatter/table owner и показывайте безопасный fallback.
