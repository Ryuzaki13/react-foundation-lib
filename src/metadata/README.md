# Внутренние скалярные метаданные

Этот каталог — приватный владелец типов скалярных значений, их классификации и
базовых типов контролов. Он не является публичной точкой входа: `index.ts` и запись
в `package.json#exports` намеренно отсутствуют. Патч меняет внутренние зависимости,
сохраняя опубликованный API и прежние имена потребителей.

Направление зависимостей:

```text
formatters / Excel / table → scalar metadata ← OData adapter
```

`ScalarMetaType` сохраняет точный действующий набор типов полей, включая
`int`, `decimal` и `datetimeOffset`. Он не расширяется значениями `number` и
`date`: они относятся к базовым типам контролов `BaseMetaType`. Изменение этого
набора потребовало бы отдельного решения о публичном API.

В этом слое нет парсера EDMX, литералов OData, схем Zod, построителей фильтров и
хранилища Zustand. Эти ответственности остаются у `odata-service`. Существующие
OData-имена классификаторов и базовых типов продолжают экспортироваться из
опубликованного `odata-service` как та же реализация и те же типы.

Функции `buildSeparatedArrays`, `findCollectionPairs` и типы коллекций «код — текст»
обслуживают OData-коллекции и остаются у `odata-service`.
Прежняя нормализация OData-ввода, значения по умолчанию и фабрики OData-форматтеров также
остаются у протокольного владельца: общий вид алгоритма не определяет его
назначение и не является основанием для переноса в общий модуль.

`bundleBoundary.test.ts` собирает пакет заново и обходит статические и
динамические зависимости опубликованных точек входа. Для общих сценариев
он запрещает реально вошедшие модули реализации OData и отдельно
проверяет сохранность полного набора опубликованных экспортов OData. Имя
сгенерированного чанка и строка `odata` внутри обычных date presets не являются
критерием утечки.
