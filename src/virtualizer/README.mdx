# Дозагрузка virtualized списка

`useFetchNextPageEffect` вызывает `fetchNextPage`, когда последняя отрендеренная virtual item достигает конца уже загруженного списка.

## Импорт

```ts
import { useFetchNextPageEffect } from "@ryuzaki13/react-foundation-lib/virtualizer";
```

Host должен использовать совместимые peer dependencies React `>=19.2 <20` и `@tanstack/react-virtual >=3.14 <4`.

## Назначение и границы

```text
virtualItems (видимый диапазон)
currentItemsCount (сколько уже загружено)
hasNextPage
          │
последний virtual index >= currentItemsCount - 1
          │
          ▼
fetchNextPage() один раз до завершения Promise
```

Hook не создаёт virtualizer, не хранит backend data, не строит query key и не решает server pagination. TanStack Query должен оставаться владельцем server snapshot.

## Сигнатура

```ts
useFetchNextPageEffect({
	virtualItems,
	currentItemsCount,
	fetchNextPage,
	hasNextPage,
	onError
});
```

| Поле                | Значение                                                            |
| ------------------- | ------------------------------------------------------------------- |
| `virtualItems`      | Текущий массив `readonly VirtualItem[]`                             |
| `currentItemsCount` | Число реально загруженных data items                                |
| `hasNextPage`       | Есть ли следующая server page                                       |
| `fetchNextPage`     | Stable функция, возвращающая Promise                                |
| `onError`           | Необязательный callback `(error: unknown) => void \| Promise<void>` |

Hook ничего не возвращает.

## Пример с TanStack Query/Virtual

```tsx
const rows = query.data?.pages.flatMap((page) => page.rows) ?? [];
const virtualItems = virtualizer.getVirtualItems();

useFetchNextPageEffect({
	virtualItems,
	currentItemsCount: rows.length,
	hasNextPage: query.hasNextPage,
	fetchNextPage: async () => {
		await query.fetchNextPage();
	}
});
```

Передавайте количество загруженных строк, а не virtual total с loader row, group headers или estimated backend count.

## Точный trigger

Fetch не запускается, если:

- `virtualItems` пуст;
- `currentItemsCount` равен `0`;
- последняя virtual item ещё не достигла `currentItemsCount - 1`;
- `hasNextPage === false`;
- предыдущий вызов ещё не завершился.

Trigger происходит строго на последнем загруженном индексе. Preload threshold «за N строк до конца» в API отсутствует.

## Защита от параллельного fetch

Внутренний single-flight ref устанавливается до вызова и сбрасывается после
успеха либо завершения обработки ошибки:

```text
idle ── trigger ──► fetchingRef=true
                       │
                 Promise pending
                       │
        resolve или завершение onError
                       ▼
                 fetchingRef=false
```

Защита действует только внутри одного mounted hook instance. TanStack Query также должен владеть дедупликацией/network state.

## Ошибки и повторная попытка

Promise rejection и синхронный throw `fetchNextPage` передаются в `onError`
один раз. Hook ожидает async callback; его собственный отказ также обрабатывается.
Без `onError`, при отказе самого callback либо после unmount исходная ошибка
остаётся в явной `console.error`-диагностике с контекстом дозагрузки. Hook не
создаёт дополнительный unhandled Promise rejection и не решает, как показывать
ошибку пользователю: это остаётся у владельца Query и UI.

После отказа hook не пытается загрузить ту же страницу при каждом scroll/render.
Неудачная попытка привязана к `currentItemsCount`: новое количество загруженных
строк либо явное выключение `hasNextPage` и последующее включение разрешают новую
попытку. Смена identity `fetchNextPage`, `onError` или `virtualItems` не является
retry. Изменение данных без изменения количества само по себе latch не снимает;
явная ручная retry-команда остаётся у владельца Query. Интервалов и собственной
retry-policy в hook нет.

## Referential stability

Effect зависит от `virtualItems`, `currentItemsCount`, `hasNextPage`, `fetchNextPage`, `onError`.

- Используйте значение virtualizer как предусмотрено его API.
- Не создавайте лишний async callback с новой identity без причины.
- React Compiler не отменяет необходимость stable external contract.
- После увеличения `currentItemsCount` новый fetch произойдёт только когда virtual range достигнет нового конца.

## Browser, SSR и lifecycle

Сам hook не читает `window`, но является React effect и не выполняет fetch во время server render. В browser effect запускается после commit.

При unmount Promise не отменяется. Abort/cancel должен быть реализован query/transport owner.
Поздний отказ не вызывает `onError` размонтированного UI, но остаётся в явной
console-диагностике. Уже начатый async `onError` не отменяется, его отказ не теряется.

## Типичные ошибки

- Передать total backend rows вместо количества загруженного массива.
- Включить client-side sorting/filtering одной страницы при server-side модели.
- Добавить фиктивный loader row в `currentItemsCount`.
- Ожидать preload заранее — trigger находится на самом конце.
- Ожидать, что hook сам покажет Query-ошибку или автоматически повторит failed page.
- Выполнять fetch прямо в row render вместо effect.
- Использовать изменяемый index как domain identity строки.

## API

```ts
type UseFetchNextPageEffectOptions = Readonly<{
	virtualItems: readonly VirtualItem[];
	currentItemsCount: number;
	hasNextPage: boolean;
	fetchNextPage: () => Promise<unknown>;
	onError?: (error: unknown) => void | Promise<void>;
}>;

function useFetchNextPageEffect(options: UseFetchNextPageEffectOptions): void;
```
